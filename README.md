## 🧭 Что это

`bedolaga-update.sh` — один bash-скрипт, который умеет:

- **Бэкапить** конфиги, базу PostgreSQL, Redis, код кабинета и Caddy — в сжатые компонентные архивы.
- **Раскладывать** копии сразу в несколько мест: локально, на SSH-сервер, в **S3**, в **Telegram**.
- **Шифровать** бэкапы ключом **age** перед отправкой наружу.
- **Восстанавливать** из любого источника (локально / SSH / S3), в том числе зашифрованные.
- **Обновлять** бота и кабинет из GitHub с пересборкой контейнеров и защитой кастомных файлов.
- **Проверять** сами бэкапы на восстановимость без отдельного сервера.

Всё управляется через понятное интерактивное меню. Настройки хранятся в `/root/.bedolaga-config` (права `600`).

Стек: Telegram-бот (remnawave) + Кабинет (cabinet-frontend) + Caddy + PostgreSQL + Redis.

## 🚀 Быстрый старт

```bash
# 1. Скачать скрипт
git clone https://github.com/Chivas600/Bedolaga-Backup-Update.git /opt/bedolaga-scripts
chmod +x /opt/bedolaga-scripts/bedolaga-update.sh

# 2. Первый запуск — интерактивная настройка
/opt/bedolaga-scripts/bedolaga-update.sh
```

При первом запуске мастер спросит:

1. IP / порт / пользователь **резервного SSH-сервера**, папку и retention;
2. **роль сервера** (всё / только бот / только кабинет);
3. пути к боту / кабинету / Caddy (ищутся автоматически);
4. домены (для health-проверок);
5. **Telegram**: токен бота, chat_id, topic_id (можно пропустить).

Дальше — меню:

```
1) 🔒 Только бэкап
2) 🔄 Только обновление
3) ⚡ Бэкап + Обновление
4) ⚙️ Настройки
5) 🔁 Восстановление из бэкапа
```

## 🧩 Выбор компонентов: бот / кабинет / всё

Частый кейс: **бот и кабинет разнесены по разным серверам**. Теперь это поддерживается двумя уровнями.

**Роль сервера** (`Настройки → 8`) — что физически стоит на хосте:

| Роль | Что бэкапится |
|------|---------------|
| `all` | бот + кабинет (+ caddy) |
| `bot` | только бот (+ caddy) |
| `cabinet` | только кабинет |

**Выбор на конкретный запуск** — при старте бэкапа скрипт спросит «Что бэкапим?», либо задайте флагом:

```bash
bedolaga-update.sh --only bot        # только бот
bedolaga-update.sh --only cabinet    # только кабинет
bedolaga-update.sh --only all        # всё
```

> На хосте с ролью `bot` кабинет никогда не трогается (и наоборот) — даже если запросить `--only all`.

## 📡 Куда складываются бэкапы (назначения)

Назначения включаются независимо в `Настройки → 7`. По умолчанию: **локально + SSH**.

```
📡 НАЗНАЧЕНИЯ БЭКАПОВ
  SSH:            true  (root@1.2.3.4)
  S3:             false
  Telegram-файлы: false
```

### SSH-сервер

Копия кладётся по `scp` на резервный сервер (ключ `/root/.ssh/id_backup`). Настраивается в `Настройки → 4`.

### S3 (Selectel и любой S3-совместимый)

`Настройки → 7 → 2`. Мастер создаёт rclone-remote и проверяет доступ к бакету:

```
Имя rclone-remote [selectel]:
Access Key ID:        <ваш ключ>
Secret Access Key:    <ваш секрет>
Endpoint [https://s3.storage.selcloud.ru]:   ← Selectel по умолчанию
Region [ru-1]:
Bucket (контейнер):   my-backups
Префикс (папка) [bedolaga-backups]:
```

Для **другого провайдера** (Cloudflare R2, Backblaze B2, AWS, MinIO, Яндекс, VK) — укажите свой `Endpoint`/`Region`, остальное так же.

Ротация на S3 идёт автоматически по тому же `retention`, что и локально.

### Telegram-файлы

`Настройки → 7 → 3`. В чат (или топик) уходят **сами файлы** бэкапа, а не только текстовый отчёт.
Файлы больше **45 МБ** автоматически режутся на части (лимит Bot API — 50 МБ). Собрать обратно:

```bash
cat bot-*.tar.zst.part* > bot.tar.zst
```

## 🔐 Шифрование age — читай обязательно

Бэкап содержит `.env` с **паролями БД, токеном бота и SMTP**. Перед отправкой в Telegram/S3 его нужно шифровать. Скрипт использует [age](https://github.com/FiloSottile/age) — простую и надёжную схему из двух ключей:

- 🔓 **Публичный ключ** — *шифрует*. Хранится на сервере, это не секрет.
- 🔑 **Приватный ключ** — *расшифровывает*. **Храните только вы.**

> ⚠️ **Без приватного ключа зашифрованный бэкап восстановить НЕВОЗМОЖНО.** Это не метафора — данные будут потеряны.

### Как включить (пошагово)

`Настройки → 9 → 1`. Мастер:

1. **Сгенерирует** пару ключей.
2. **Крупно покажет приватный ключ** с предупреждением.
3. Предложит **прислать ключ и инструкцию в Telegram** (с пометкой «сохрани и удали сообщение»).
4. **Заставит подтвердить**, что вы сохранили ключ — попросит ввести его **последние 8 символов**.
5. Спросит, **хранить ли приватный ключ на сервере** (по умолчанию **нет** — так безопаснее).
6. В конфиг запишет **только публичный ключ**, включит шифрование.

### Что вам нужно сделать (правило трёх шагов)

> **Нажал → Записал → Сохранил → работает.**
> 1. **Нажал** — запустил мастер, увидел приватный ключ `AGE-SECRET-KEY-...`.
> 2. **Записал** — скопировал его в менеджер паролей (Bitwarden/1Password/KeePass) или в надёжное место.
> 3. **Сохранил** — подтвердил вводом последних 8 символов.
> После этого offsite-копии становятся `*.tar.zst.age`, и восстановиться можно только с этим ключом.

### Как восстановить зашифрованный бэкап

Запустите восстановление — если бэкап зашифрован, скрипт попросит **вставить приватный ключ**. Вставляете строку `AGE-SECRET-KEY-...`, Enter — и всё расшифруется. Ключ на сервере не сохраняется (используется временно и стирается).

## 🔁 Восстановление

`Меню → 5`. Скрипт спросит **источник**:

```
Откуда восстанавливаем?
  1) Локально
  2) SSH-сервер
  3) S3
```

Дальше — выбор конкретного бэкапа, **тройное подтверждение** (последнее — ввод слова `RESTORE`), и восстановление:

- проверка `SHA256SUMS`;
- расшифровка (если нужно);
- распаковка архивов;
- `pg_restore` базы, восстановление Redis, конфигов, кода кабинета, Caddyfile;
- перезапуск контейнеров и health-проверка.

Восстанавливаются и **новые (v3)**, и **старые (v2)** бэкапы.

## 🔎 Проверка восстановления (--verify-restore)

Проверяет, что последний бэкап реально восстановим — **без отдельного стенда и без риска для боевой БД**:

```bash
bedolaga-update.sh --verify-restore
```

- **Уровень 1:** сверка `SHA256`, целостность архивов, тест расшифровки, `pg_restore --list`.
- **Уровень 2:** реальный `pg_restore` в **одноразовый изолированный** контейнер PostgreSQL (без портов и боевых томов), подсчёт таблиц, затем контейнер удаляется. Боевая БД не затрагивается.

Итог дублируется в Telegram. Можно вешать на отдельный (более редкий) cron.

## ⏰ Автобэкап по расписанию (cron)

`Настройки → 5` — задать час и минуту. Пишется в `/etc/cron.d/bedolaga-backup`:

```cron
0 3 * * * root /opt/bedolaga-scripts/bedolaga-update.sh --cron >> /var/log/bedolaga-cron.log 2>&1
```

В cron-режиме бэкапится всё, что есть на хосте (по роли). Можно сузить: `--cron --only bot`.

## 🔄 Обновление бота и кабинета

`Меню → 2` (или `3` — бэкап + обновление). Скрипт:

1. сохраняет кастомные файлы (список в `/root/.bedolaga-custom-files`, `Настройки → 6`);
2. `git reset --hard` до актуального релиза;
3. возвращает кастомные файлы;
4. пересобирает и поднимает контейнеры;
5. проверяет health.

Обновление тоже уважает роль хоста (на `bot`-хосте кабинет не трогается).

### Защита кастомных правок при обновлении

Два механизма (оба применяются вокруг `git reset --hard`):

- **Кастомные файлы** (`Настройки → 6`, `/root/.bedolaga-custom-files`) — целиком сохранить и вернуть свои файлы (напр. `vpn_logo.png`).
- **Инъекции строк** (`Настройки → 10`, `/root/.bedolaga-inject`) — дописать нужную строку в апстримный файл, если её там нет. Идемпотентно, не морозит файл целиком. Формат `файл | якорь | сниппет`:
  ```
  index.html | </body> | <script src="https://help.whiterabbit.st/widget.js"></script>
  ```
  Применяется после `git reset` и **до** `npm run build`, поэтому попадает в сборку. Для одной строки (виджет, счётчик) это предпочтительнее, чем замораживать весь `index.html`.

## 🛠 Troubleshooting

| Симптом | Причина / решение |
|--------|-------------------|
| `Конфиг не найден` в cron | Сначала запустите скрипт интерактивно (создаст `/root/.bedolaga-config`) |
| `Другой экземпляр уже выполняется` | Активен flock — параллельный запуск пропускается, это норма |
| `pg_restore --list — повреждён` | БД-дамп не создался (контейнер БД недоступен?) — бэкап прерван, проверьте PostgreSQL |
| `S3: нет доступа к бакету` | Проверьте Access/Secret ключи, endpoint, имя бакета |
| Telegram-файл не ушёл | Файл >50 МБ (режется автоматически) или неверный токен/chat_id |
| `Нужен приватный age-ключ` при restore | Вставьте строку `AGE-SECRET-KEY-...`; без неё зашифрованный бэкап не восстановить |
| Бэкап «молчит» ночью | При сбое приходит алерт в Telegram; смотрите `/var/log/bedolaga-cron.log` |

## ❓ FAQ

**Можно ли бэкапить только бота, а кабинет на другом сервере — только кабинет?**
Да. На каждом хосте задайте роль (`Настройки → 8`): `bot` и `cabinet` соответственно.

**Потеряю ли я старые бэкапы после обновления до v3?**
Нет. v2-бэкапы (россыпь файлов) полностью поддерживаются при восстановлении.

**Обязательно ли шифрование?**
Для offsite (Telegram/S3) — крайне желательно: в `.env` лежат секреты. Локально можно без него.

**Что если потеряю приватный age-ключ?**
Зашифрованные бэкапы станут нечитаемыми. Храните ключ в менеджере паролей. Незашифрованные локальные копии (если включены) не пострадают.

**Не сломает ли `--dry-run` прод?**
Нет. Он не отправляет, не удаляет и не меняет боевые сервисы.
